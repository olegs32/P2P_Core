# P2P Core

## Что это за проект

Это программа, которая превращает несколько обычных компьютеров в **единую самоорганизующуюся сеть** — без центрального сервера.

Представьте: есть десяток машин в разных кабинетах или филиалах. Каждая запускает один файл — и они сами находят друг друга, сами договариваются, кто с кем соединён, и сами передают команды и данные даже тем машинам, к которым нет прямого доступа (через «соседей по цепочке»).

Каждый компьютер в этой сети называется **узлом** (node). Управлять всей сетью можно через **веб-панель** — обычную страницу в браузере, открытую на любом из узлов.

## Зачем он создавался

Проект вырос из реальной задачи: **управлять сертификатами КриптоПро на множестве машин**.

Раньше, чтобы установить/переустановить/выгрузить сертификат на удалённой машине, нужно было физически к ней идти или подключаться вручную. Теперь достаточно открыть веб-панель:

- посмотреть, какие сертификаты установлены на любом узле сети;
- установить сертификат с одного узла на другой прямо через сеть;
- найти сертификаты по имени владельца по всей сети.

Вторая задача, под которую проект заточен — **распределённые вычисления**: одна машина может «раздать» часть работы другим и собрать результат, даже если они не соединены напрямую.

По сути это каркас (платформа): базовая сеть уже работает, а конкретные умения добавляются как **сервисы** — небольшие подключаемые модули. Сертификаты — первый такой сервис, вычисления — второй. Новый функционал пишется отдельным модулем, кладётся в папку `services/` — и он появляется во всей сети, даже без перезапуска узла.

## Как это работает (без технических деталей)

- Узлы соединяются друг с другом напрямую (достаточно указать адрес хотя бы одного соседа).
- Каждый узел рассказывает соседям о том, кого знает сам. Так информация о всей сети расходится от узла к узлу — сеть «сама себя узнаёт».
- Если два узла не соединены напрямую, команда к дальнему узлу идёт через промежуточные — как письмо через почту.
- Никакого главного сервера: выход из строя любого узла не ломает сеть.
- На каждом узле крутится локальная страница управления (порт 8501), откуда видно всю сеть.

## Что уже умеет

| Возможность | Что это значит на практике |
|---|---|
| Веб-панель | Управление любым узлом сети из браузера |
| Сертификаты КриптоПро | Просмотр, установка, экспорт, поиск; передача сертификата с машины на машину |
| Подключение узлов | Присоединить новую машину к сети прямо из панели |
| Диагностика сети | Кто с кем соединён, какие сервисы где живут |
| Просмотр логов | Консольные логи любого узла прямо в панели: фильтры по уровню/тексту, живое обновление, экспорт |
| Распределённые вычисления | Передача потока данных между машинами частями, с контролем нагрузки |
| Горячее обновление сервисов | Новый модуль подхватывается без перезапуска |

## Быстрый старт

Нужен Python 3.11+ (разработка ведётся на Windows).

```bash
pip install -r requirements.txt
python main.py
```

При первом запуске рядом появится `config.yaml` с настройками по умолчанию. Затем откройте в браузере:

```
http://localhost:8501
```

Чтобы добавить в сеть вторую машину: запустите там так же `main.py`, затем в веб-панели откройте вкладку **«Система» → «Подключение»**, введите адрес первой машины — узлы соединятся, и подключение запомнится для будущих запусков.

Проверочный клиент для тестов сети: `python debug_client.py`.

## Структура репозитория

```
main.py          — запуск узла
services/        — подключаемые сервисы (каждая папка = один сервис)
services/demo/   — эталонный пример сервиса с пояснениями (начните знакомство с него)
services/logs/   — просмотр консольных логов узла в веб-панели
src/             — ядро: сеть, маршрутизация, конфигурация
webpanel         — веб-панель (это тоже сервис, лежит в services/webpanel)
compile.py       — сборка готовых exe-файлов (с панелью и без неё)
docs/README.md   — подробная техническая документация
glm.md           — краткая база знаний по архитектуре (для людей и AI)
roadmap.md       — планы развития
```

## Куда смотреть дальше

- Хотите понять систему глубоко → `docs/README.md` (полное описание архитектуры).
- Нужно быстро вспомнить, что где лежит → `glm.md`.
- Интересно, что планируется → `roadmap.md`.
- Хотите добавить свой сервис → раздел «Создание нового сервиса» в `docs/README.md`: это одна папка с одним файлом и парой функций.
